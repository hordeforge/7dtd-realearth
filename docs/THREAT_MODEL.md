## 2. Assets

- **Dedicated-server process integrity/availability.** Mod runs in-process (Harmony) in client and dedicated host (`Source/RealEarth/ModApi.cs`); any decode/fetch bug carries game-process authority.
- **World saves and live chunks.** Terrain inject mutates live engine chunks through reflection (`Source/RealEarth/ChunkTerrainInject.cs:8-16`); persistent state is written by `WorldSavePath.cs:20-33`, `SessionStateStore.cs:265-294` and `AtomicPublish.cs:19-25`. Poisoned or corrupt tiles produce persistent world corruption, and a tampered session snapshot silently relocates a world's origin.
- **Game install directories.** Tile cache writes (`TileStreamer.cs:502-506`), baked worlds under `GeneratedWorlds`. No game assembly is written by this repo.
- **Pipeline durable state.** Baked worlds/packs (`worlds/`, `data/samples/`), the Terrarium source-tile cache (`data/cache/terrarium`, the only hedge against upstream dataset loss), and backup archives (`scripts/backup_artifacts.sh:217-231`); all git-ignored and not rebuildable without network.
- **Terrain data fidelity = gameplay fairness.** Elevation/population decide traversal, spawn, city density; a hostile pack is a cheat/griefing primitive.
- **Project reputation.** Operators install mods/packs trusting provenance; nothing here signs artifacts.
- **Not held:** user PII, payment data, signing keys, stored credentials. The only credential-shaped value in the tree is the test telnet password, shipped empty with telnet disabled (`scripts/serverconfig_height_test.xml:41-45`).

## 4. Trust boundaries and flows

- **B1 Remote tile CDN → game process.** Crosses on every miss when `TileCdnBaseUrl` is set (`RealEarthConfig.cs:58`, default empty so nothing is fetched unless configured). Validation points: https-only URL policy with userinfo/CRLF/host checks (`CdnTilePolicy.cs:13-33`), fetch-time re-check plus redirect-downgrade rejection (`TileStreamer.cs:543-548`), magic-byte gate (`TileStreamer.cs:488,687`), and a full `RteTile.Decode` of the body before the bytes are published to the durable tile store (`TileStreamer.cs:495-506,696-701`). Content authenticity remains unnamed territory (T2).
- **B2 Third-party APIs → pipeline workstation → durable cache.** open-meteo/S3 responses decoded offline (`elevation.py:63-95,223-300`). No validation beyond PNG/library decode, and fetched Terrarium tiles persist to `RE_TERRARIUM_CACHE` (`elevation.py:159-162,173-189`) where later builds serve them back without any re-check (`elevation.py:270-276`): a poisoned or silently corrupted cache becomes world truth on every future rebuild (extends T2's persistence half to the pipeline). Deps pinned by `tools/uv.lock`.
- **B3 Pack author → operator → game/pipeline/viewer.** `.rte`, `earth.manifest.json`, `build.json`, `settlements.json`, GeoTIFFs. No signatures; manifest notes are free text. `build.json` records sha256 of pipeline inputs (`region.py:291,323`) and `realearth verify-build` re-checks them against disk (`cli.py:103-147`), which catches a locally altered or half-rebuilt pack but proves nothing about the publisher. Downstream echo surfaces sanitize (CLI `_display_text` `cli.py:67-74`; viewer server logs `viewer_server.py:91-99`); path-joining of pack names rejects traversal components (`cli.py:77-87`); C# ingestion normalizes names to NFC and strips C0/C1 control chars before they reach log lines (`CityMapLabels.cs:55-88`, applied at `:699,704,954`).
- **B4 Browser ↔ viewer/webmod.** Viewer origin renders pack strings through text-only DOM APIs; served responses carry CSP/nosniff/frame-deny/referrer-policy/permissions-policy (`viewer_server.py:100-121`) with listings blocked by an override (`viewer_server.py:123-127`); translated paths must stay inside the served tree (`viewer_server.py:145-155`). three.js is served from the same origin as a committed file (`viewer/index.html:28-35`), so the viewer trust boundary is closed: no remote script origin remains, and the CSP grants none. WebMod executes within the game's authenticated dashboard session (game owns that boundary); its pack field is passed to the shared `loadPack`, which applies `isSafePackPath` (`webmod/src/map-page.ts:564` → `viewer/src/pack.ts:283-287`).
- **B5 Operator ↔ install tooling / backup tooling.** Install targets Steam dirs through env-resolved roots (`install_proton.sh:10-11`) behind existence checks on the game payload and Harmony (`install_proton.sh:28-35`). No `rm` runs in the install script itself: `atomic_dir_swap` builds a sibling staging dir, registers it with an `EXIT` trap, and only then moves the live mod folder aside and renames staging onto it (`atomic_dir_swap.sh:14-47`, `install_proton.sh:112-121`), so a failed copy leaves the previous install loadable. Config and serverconfig writing runs as `realearth.mod_config` / `realearth.server_config` with values passed as argv, so an env-supplied world name or userdata path is data, never Python or XML source. The height-test harness moves old saves into a 7-day trash window instead of deleting them (`run_dedicated_height_test.sh:168-191`). Artifact restore verifies sha256/gzip and refuses to clobber existing dirs unless `RE_FORCE_RESTORE=1` (`backup_artifacts.sh:314-326,344-373`), but otherwise trusts the archive it is pointed at; the roundtrip including those guardrails is proven on synthetic state by `make artifacts-drill` (`scripts/artifacts_drill.sh`, `ci.yml:55`). Operator trust assumed; not sandboxed.
- **B6 Build → runtime.** The mod ships as one Harmony assembly and patches the engine in memory: `RuntimeYDimTranspiler` rewrites the Y-bound literals and layer-array sizes at JIT time (`RuntimeYDimTranspiler.cs:9-27,38-59`) and never writes a file. That DLL is the whole privileged artifact, so the control that matters is provenance of `RealEarth.dll` and of the game build it binds to. `BuildGuard` hashes the loaded `Assembly-CSharp.dll` at init and refuses height inject on any build not in its reviewed sha256 allowlist, fail-closed unless the operator sets `EngineHeightAllowUnknownBuild` (`BuildGuard.cs:66-100`; `ModApi.cs:163-175`; `RealEarthConfig.cs:159`). The allowlist currently carries three V3.2.0 (b9) hashes (`BuildGuard.cs:20-23`); a Steam update drops the build into the unknown branch until someone re-reviews it. `realearth engine-audit` is a read-only metadata probe of the game's YDim constants (`cli.py:650-672`, `tools/realearth/engine_constants.py`); it changes nothing. Provenance of the shipped artifact: release tags must match the version in `ModInfo.xml` (and in `tools/realearth/__init__.py`) or the workflow fails (`release.yml:34-60`), Actions are pinned by full commit SHA with the tag in a comment (`release.yml:29-31`, `ci.yml:23-26`), and the JS toolchain is pinned in one sourced file consumed by every build/lint script (`toolchain-versions.env:24-56`) with the installed tree frozen against the committed `scripts/js-toolchain.lock` (`install-js-toolchain.sh:53,91-93`).
- **B7 Secrets → code.** No credentials stored or rotated here. Telnet ships disabled with an empty password (`scripts/serverconfig_height_test.xml:41-45`); the CDN URL is configuration, not a secret.
- **B8 World save → mod session state.** A save directory is routinely copied between players, traded, or downloaded. The mod writes `realearth.session.json` into it (`WorldSavePath.cs:20-33`, `SessionStateStore.cs:265-294`) and reads it back on load (`SessionStateStore.cs:297-340`), so a save from an untrusted source carries attacker-chosen origin, absolute position, spawn coordinates and a discovered-city list. Cross-world confusion is already guarded: each snapshot carries a hashed world-save identity and restore skips a snapshot whose scope does not match the current world (`SessionStateStore.cs:101-117,325-331`). What is not guarded is size: the file is read whole with `File.ReadAllText` and the reader is a hand-rolled scanner (`SessionStateStore.cs:122-131`), so a megabyte-scale file is parsed on the load path (T10). Discovered-city strings are catalog keys and pass through `NormalizePlaceName` (`CityMapLabels.cs:158-174`), so a hostile name cannot forge game-log lines.

Privilege transitions: pipeline shell → game install files (B5); mod tooling → in-process engine behavior via Harmony, with no file write (B6); tile bytes → in-process decoder running with server privileges (B1/B3 → E1/E2); third-party save file → world origin and marker placement (B8 → E5).

## 5. Threats per boundary (STRIDE)

- **B1:** Tampering/Spoofing: a hijacked https CDN or TLS-breaking MITM swaps `.rte`; poison persists via cache (T2). DoS: response sizes and inflate output are capped (`TileStreamer.cs:551-568`; `RteTile.cs:198-212`); refetch churn is bounded by the negative cache with a prune threshold (`TileStreamer.cs:63,83,629-665`) and in-flight dedup (`TileStreamer.cs:470-477`). Disclosure: none expected (public Earth data).
- **B2:** Tampering: hostile upstream elevation/population silently becomes world truth; no cross-source check. Persistence half: poisoned Terrarium tiles land in the disk cache and outlive the hostile run (`elevation.py:173-189`). DoS: large PNG decode on a workstation; low impact offline.
- **B3:** Elevation of trust: untrusted pack gets full terrain+POI authority once installed (T1). Repudiation: `sources_note` and `build.json` hashes prove reproducibility of a local build, not provenance of the pack.
- **B4:** Tampering/XSS: currently no HTML sink in either app (T7 is a regression-watch row). Script supply chain: closed by vendoring plus a byte-compare and pinned-sha256 gate (T8 retired); WebMod runs with admin-session authority and its fetch target is path-guarded by the shared pack module. DoS: `ThreadingHTTPServer` spawns a thread per connection with no rate limit (`viewer_server.py:216`); loopback-by-default keeps this local.
- **B5:** Data loss: wrong env var redirects destructive paths; mitigated by existence checks, staging + move-aside, and the saves trash window, not dry-run defaults. Restore pointed at a hostile archive writes wherever its members name (operator-supplied input assumed benign); the drill proves the guards work on synthetic state but cannot vouch for a hostile archive's contents.
- **B6:** Persistent code injection via a tampered mod DLL (T4); the release tag gate and SHA-pinned actions narrow who can produce one. The transpiler's own residual is documented in code: a site another mod JITs before the transpiler is installed leaves a half-patched engine (`RuntimeYDimTranspiler.cs:12-15`), which is an integrity/fail-safe concern rather than an attacker-reachable one. Toolchain pins are centralized in `toolchain-versions.env` (anti-slop tarball by commit SHA and sha256 at `:40-41`) and CI Actions are pinned by commit SHA; tiles and packs still lack an equivalent.
- **B8:** Tampering: a hand-edited snapshot relocates a world (cheat, or a grief vector in a shared save). DoS: unbounded read plus hand-rolled parse on the load path (T10). Spoofing: a snapshot cannot cross world scope, but a snapshot copied wholesale into another world with the same scope hash replays that world's origin. Elevation: the discovered-city list seeds marker placement, so a hostile list can name arbitrary catalog cities; it cannot inject code, only wrong markers (T10).
- **E6 telnet/console:** Elevation via password guessing is game-owned control; the template no longer contributes a weak value (telnet ships disabled; T6 residual is operator re-enable).

DoS summary: the dedicated hot path is bounded end to end (fetch cap → header gate → inflate cap → dims/section-length checks → decode before persist); what remains is CPU cost per hostile tile, unthrottled connections on the dev viewer server, and the unbounded session-file read on world load.

### Gaps (ranked; fixes go to sec-review)

1. No authenticity check for tiles/packs anywhere in the chain: no signature, no hash pinning. Runtime CDN fetch, installed packs, *and* the pipeline's Terrarium disk cache (`elevation.py:159-189`) all trust bytes on transport alone, so transport hardening does not help against the CDN itself or a malicious pack publisher (T1, T2). `verify-build` and `build.json` cover local reproducibility only.
2. The session-state read is unbounded and its parser is hand-rolled. `File.ReadAllText` on a file that arrives inside a shared save, then a scanner that finds keys by substring match (`SessionStateStore.cs:122-131`), with no length cap and no field-count or `discoveredCities` count limit on the load path (`SessionStateStore.cs:297-340,343`). A hostile save can make world load allocate and parse arbitrarily. The numeric fields are clamped downstream, so this is availability, not injection (T10).
3. `BuildGuard`'s allowlist carries three V3.2.0 (b9) hashes (`BuildGuard.cs:20-23`); any Steam update lands in the fail-closed unknown branch until the list is refreshed. The gate is correct, the list is the maintenance burden.
4. `realearth serve --bind` past loopback serves everything under the viewer root unauthenticated by design; the warning (`cli.py:965-970`) is the only control (T3).
5. Residual decode cost: a hostile CDN can still spend server CPU on up-to-64 MB payloads per in-flight tile; fan-out is bounded by radius, negative cache, concurrency cap and in-flight dedup but not rate-limited (T5).
6. No structured security events; failures go to the game log via `ModLog.Log` (`ModLog.cs:106-107`). Note only; o11y-review owns log structure.

Single points of failure: `RteTile.Decode` is the sole gate for local and CDN bytes (hardening it covers E1+E2 at once), and `CdnTilePolicy.TileUrl` is the sole gate for outbound tile URLs.

Documented-but-not-implemented check: two claims were false in earlier revisions and are now removed (a disk-patch/backup/`--verify` pipeline under `Program.cs`, and a live CSP grant for `cdn.jsdelivr.net`). Remaining claims were re-read against code this pass: the `MODLET.md:61-64` config-validation claim matches `RealEarthConfig.Validate()` (`RealEarthConfig.cs:304-500`); the `BACKUP_RESTORE.md` checksum/refuse-overwrite claims match `backup_artifacts.sh:217-231,314-326,344-373` and its restore-drill claim is implemented (`scripts/artifacts_drill.sh`, `ci.yml:55`); `SECURITY.md`'s three claims about the vendored viewer, the report channel and the release tag gate all hold.

## 7. Abuse cases

- **Pack poisoning.** A publisher ships a "free full-Earth" pack with altered heights/population; operators install it; players get unfair geometry/loot. Path: E2 accepts any well-formed RTE1 (`RteTile.cs:48`), gap 1.
- **CDN-borne terrain rewrite.** Whoever controls or compromises the configured https CDN rewrites tiles; they pass the magic gate and the full decode, then land in the disk cache, poisoning later sessions even after the CDN is fixed. Path: `TileStreamer.cs:687-701`, gap 1.
- **Pipeline-cache poisoning.** A compromised workstation or hostile mirror serves Terrarium PNGs once; they are stored to the disk cache and every future rebuild trusts them (`elevation.py:270-276`), silently baking altered elevation into new packs. Same class as the previous case, offline half of gap 1.
- **Shared-save session hijack.** A player receives a "pre-seeded" world save whose `realearth.session.json` names a chosen origin, spawn and city list. On load the mod adopts it (`SessionStateStore.cs:297-340`); the world starts wherever the file says and stamps the named cities. Scope gate stops cross-world replay, not a file shipped inside the right world (T10).
- **Viewer-borne script execution (regression watch).** A shared viewer pack embeds markup in a settlement name; operator previews via `realearth serve`. Today nothing renders it as HTML (`viewer/src/app.ts:358-370` builds text nodes), so this is the scenario to re-test if an HTML sink ever appears. Recorded as scenario, not demonstrated.
- **Half-patched engine via load order.** Another mod JITs a Y-bound method before `RuntimeYDimTranspiler` installs, leaving the engine with mixed vertical bounds: terrain or lighting computed against a different YDim than storage allocates. Documented in `RuntimeYDimTranspiler.cs:12-15`; the trigger is mod ordering, not an attacker, but the failure mode is silent world corruption.
- **Authenticated-player resource churn.** Position spam creates focus churn; each new area triggers bounded CDN/disk loads. Path: focus register (`WorldSession.cs:291-320`) → `TileStreamer.UpdateFromAbsolute` (`TileStreamer.cs:182-214`); bounds: `StreamRadiusTiles`/`UnloadRadiusTiles` (`RealEarthConfig.cs:24-25`), miss cache + prune (`TileStreamer.cs:629-665`), concurrency cap (`TileStreamer.cs:95,571-579`), in-flight dedup, stale-focus TTL (`TileStreamer.cs:78,261`). Amplification against the configured CDN host is capped today.
- **Client-side enforcement:** none relied on; reveal/debug helpers are config-gated server-side (`MapReveal.cs:36-48`, `DebugRevealFullMap` default false `RealEarthConfig.cs:73`).

## 8. Response readiness (note only)

- Reporting channel documented ([`../SECURITY.md`](../SECURITY.md)); no documented path from "vulnerability reported" to "fix shipped" beyond it.
- Audit trail after an incident is thin: game log lines only (`ModLog.Log`). o11y-review owns log structure; sec-review should treat gaps 1-6 above as its aiming list. Durability of evidence itself is covered by [`BACKUP_RESTORE.md`](BACKUP_RESTORE.md) (artifact archives), not by any log retention policy.
