## 2. Assets

- **Dedicated-server process integrity/availability.** Mod runs in-process (Harmony) in client and dedicated host (`Source/RealEarth/ModApi.cs`); any decode/fetch bug carries game-process authority.
- **World saves.** Terrain inject mutates chunks/saves (`Source/RealEarth/ChunkTerrainInject.cs`); poisoned/corrupt tiles corrupt persistent worlds.
- **Game install directories.** Tile cache writes (`TileStreamer.cs:453-454`), baked worlds under `GeneratedWorlds`. No game assembly is written by this repo.
- **Pipeline durable state.** Baked worlds/packs (`worlds/`, `data/samples/`), the Terrarium source-tile cache (`data/cache/terrarium`, the only hedge against upstream dataset loss), and backup archives (`scripts/backup_artifacts.sh:1-19`); all git-ignored and not rebuildable without network.
- **Terrain data fidelity = gameplay fairness.** Elevation/population decide traversal, spawn, city density; a hostile pack is a cheat/griefing primitive.
- **Project reputation.** Operators install mods/packs trusting provenance; nothing here signs artifacts.
- **Not held:** user PII, payment data, signing keys, stored credentials. The only credential-shaped value in the tree is the test telnet password, shipped empty with telnet disabled (`scripts/serverconfig_height_test.xml:42-45`).

## 4. Trust boundaries and flows

- **B1 Remote tile CDN → game process.** Crosses on every miss when `TileCdnBaseUrl` is set (`RealEarthConfig.cs:47`, default empty so nothing is fetched unless configured). Validation points: https-only URL policy with userinfo/CRLF/host checks (`CdnTilePolicy.cs:13-33`), fetch-time re-check plus redirect-downgrade rejection (`TileStreamer.cs:490-495`), magic-byte gate (`TileStreamer.cs:437,602`), and a full `RteTile.Decode` of the body before the bytes are published to the durable tile store (`TileStreamer.cs:452-454,610-613`). Content authenticity remains unnamed territory (T2).
- **B2 Third-party APIs → pipeline workstation → durable cache.** open-meteo/S3 responses decoded offline (`elevation.py`). No validation beyond PNG/library decode, and fetched Terrarium tiles persist to `data/cache/terrarium` (`elevation.py:151-184`) where later builds serve them back without any re-check (`elevation.py:263-275`): a poisoned or silently corrupted cache becomes world truth on every future rebuild (extends T2's persistence half to the pipeline). Deps pinned by `tools/uv.lock`.
- **B3 Pack author → operator → game/pipeline/viewer.** `.rte`, `earth.manifest.json`, `build.json`, `settlements.json`, GeoTIFFs. No signatures; manifest notes are free text. `build.json` records sha256 of pipeline inputs and `realearth verify-build` re-checks them against disk (`cli.py:71-105`), which catches a locally altered or half-rebuilt pack but proves nothing about the publisher. Downstream echo surfaces sanitize (CLI `_display_text` `cli.py:35-43`; viewer server logs `viewer_server.py:48-56`); path-joining of pack names rejects traversal components (`cli.py:46-57`); C# ingestion normalizes names to NFC and strips C0/C1 control chars before they reach log lines (`CityMapLabels.cs:51-77`, applied at `:638,643,893`).
- **B4 Browser ↔ viewer/webmod.** Viewer origin renders pack strings through text-only DOM APIs; served responses carry CSP/nosniff/frame-deny/referrer-policy/permissions-policy (`viewer_server.py:64-77`) with listings blocked by an override (`viewer_server.py:79-83`); translated paths must stay inside the served tree (`viewer_server.py:102-113`). three.js is served from the same origin as a committed file (`viewer/index.html:13-18`), so the viewer trust boundary is closed: no remote script origin remains. The CSP still names `https://cdn.jsdelivr.net` in `script-src` and `index.html:12` still preconnects to it; nothing loads from there, so this is unused permission rather than exposure (T9). WebMod executes within the game's authenticated dashboard session (game owns that boundary); its pack/file fields pass the same path guard as the viewer through the shared module (`webmod/src/pack.ts:1-13` re-exporting `viewer/src/pack.ts:19-35`).
- **B5 Operator ↔ install tooling / backup tooling.** Scripts remove guarded destinations inside Steam dirs (`install_proton.sh:75`); gated by explicit `GAME_DIR` existence checks (`install_proton.sh:24-31`; roots resolved via `SEVENDTD_GAME_DIR`/`SEVENDTD_SERVER_DIR`, `install_proton.sh:6-7`, `tools/realearth/proton_paths.py`). Config and serverconfig writing runs as `realearth.mod_config` / `realearth.server_config` with values passed as argv, so an env-supplied world name or userdata path is data, never Python or XML source. The height-test harness moves old saves into a 7-day trash window instead of deleting them (`run_dedicated_height_test.sh:168-180`). Artifact restore verifies sha256/gzip and refuses to clobber existing dirs unless `RE_FORCE_RESTORE=1` (`backup_artifacts.sh:112-118,129-145`), but otherwise trusts the archive it is pointed at; the roundtrip including those guardrails is proven on synthetic state by `make artifacts-drill` (`scripts/artifacts_drill.sh`, `ci.yml:51`). Operator trust assumed; not sandboxed.
- **B6 Build → runtime.** The mod ships as one Harmony assembly and patches the engine in memory: `RuntimeYDimTranspiler` rewrites the Y-bound literals and layer-array sizes at JIT time (`RuntimeYDimTranspiler.cs:9-26,38-59`) and never writes a file. That DLL is the whole privileged artifact, so the control that matters is provenance of `RealEarth.dll` and of the game build it binds to. `BuildGuard` hashes the loaded `Assembly-CSharp.dll` at init and refuses height inject on any build not in its reviewed sha256 allowlist, fail-closed unless the operator sets `EngineHeightAllowUnknownBuild` (`BuildGuard.cs:17-24,68-100`; `ModApi.cs:140-150`; `RealEarthConfig.cs:147`). The allowlist currently carries three V3.2.0 (b9) hashes (`BuildGuard.cs:20-23`); a Steam update drops the build into the unknown branch until someone re-reviews it. `realearth engine-audit` is a read-only metadata probe of the game's YDim constants (`cli.py:595-602`, `tools/realearth/engine_constants.py`); it changes nothing. Provenance of the shipped artifact: release tags must match the version in `ModInfo.xml` or the workflow fails (`release.yml:31-47`), Actions are pinned by full commit SHA with the tag in a comment (`release.yml:27-29`, `ci.yml:26-27`), and the JS toolchain is pinned in one sourced file consumed by every build/lint script (`toolchain-versions.env:22-52`) with resolved artifacts fixed and hash-verified by the committed `scripts/js-toolchain.lock`. The vendored three.js is hash-compared to the pinned `node_modules` copy on every `make viewer-build` (`scripts/vendor-three.sh:60-69`, `Makefile:369`).
- **B7 Secrets → code.** No credentials stored or rotated here. Telnet ships disabled with an empty password (`scripts/serverconfig_height_test.xml:42-45`); the CDN URL is configuration, not a secret.


Privilege transitions: pipeline shell → game install files (B5); mod tooling → in-process engine behavior via Harmony, with no file write (B6); tile bytes → in-process decoder running with server privileges (B1/B3 → E1/E2).

## 5. Threats per boundary (STRIDE)

- **B1:** Tampering/Spoofing: a hijacked https CDN or TLS-breaking MITM swaps `.rte`; poison persists via cache (T2). DoS: response sizes and inflate output are capped (`TileStreamer.cs:496-514`; `RteTile.cs:182-189`); refetch churn is bounded by the negative cache with a prune threshold (`TileStreamer.cs:26,65,553-573`) and in-flight dedup (`TileStreamer.cs:29,517-528`). Disclosure: none expected (public Earth data).
- **B2:** Tampering: hostile upstream elevation/population silently becomes world truth; no cross-source check. Persistence half: poisoned Terrarium tiles land in `data/cache/terrarium` and outlive the hostile run (`elevation.py:165-184`). DoS: large PNG decode on a workstation; low impact offline.
- **B3:** Elevation of trust: untrusted pack gets full terrain+POI authority once installed (T1). Repudiation: `sources_note` and `build.json` hashes prove reproducibility of a local build, not provenance of the pack.
- **B4:** Tampering/XSS: currently no HTML sink in either app (T7 is a regression-watch row). Script supply chain: closed by vendoring, gated by a CI hash check (T8 retired); WebMod runs with admin-session authority and its fetch targets are path-guarded through the shared pack module. DoS: `ThreadingHTTPServer` spawns a thread per connection with no rate limit (`viewer_server.py:151`); loopback-by-default keeps this local.
- **B5:** Data loss: wrong env var redirects destructive paths; mitigated by existence checks and the saves trash window, not dry-run defaults. Restore pointed at a hostile archive writes wherever its members name (operator-supplied input assumed benign); the drill proves the guards work on synthetic state but cannot vouch for a hostile archive's contents.
- **B6:** Persistent code injection via a tampered mod DLL (T4); the release tag gate and SHA-pinned actions narrow who can produce one. The transpiler's own residual is documented in code: a site another mod JITs before the transpiler is installed leaves a half-patched engine (`RuntimeYDimTranspiler.cs:11-15`), which is an integrity/fail-safe concern rather than an attacker-reachable one. Toolchain pins are centralized in `toolchain-versions.env` (anti-slop tarball by commit SHA and sha256 at `:39-42`) and CI Actions are pinned by commit SHA; tiles and packs still lack an equivalent.
- **E4 telnet/console:** Elevation via password guessing is game-owned control; the template no longer contributes a weak value (telnet ships disabled; T6 residual is operator re-enable).

DoS summary: the dedicated hot path is bounded end to end (fetch cap → header gate → inflate cap → dims/section-length checks → decode before persist); what remains is CPU cost per hostile tile and unthrottled connections on the dev viewer server.

### Gaps (ranked; fixes go to sec-review)

1. No authenticity check for tiles/packs anywhere in the chain: no signature, no hash pinning. Runtime CDN fetch, installed packs, *and* the pipeline's Terrarium disk cache (`elevation.py:151-184`) all trust bytes on transport alone, so transport hardening does not help against the CDN itself or a malicious pack publisher (T1, T2). `verify-build` and `build.json` cover local reproducibility only.
2. `BuildGuard`'s allowlist carries three V3.2.0 (b9) hashes (`BuildGuard.cs:20-23`); any Steam update lands in the fail-closed unknown branch until the list is refreshed. The gate is correct, the list is the maintenance burden.
3. `realearth serve --bind` past loopback serves everything under the viewer root unauthenticated by design; the warning (`cli.py:903-907`) is the only control (T3).
4. Residual decode cost: a hostile CDN can still spend server CPU on up-to-64 MB payloads per in-flight tile; fan-out is bounded by radius, negative cache, and in-flight dedup but not rate-limited (T5).
5. Dead CSP permission: `script-src` still lists `https://cdn.jsdelivr.net` and `index.html:12` still preconnects to it, with no code path that loads from that origin (`viewer_server.py:70`, `viewer/index.html:12`). Not exploitable today; it widens the blast radius of any future CSP regression or injected tag. Narrowing `script-src` to `'self' 'unsafe-inline'` is a one-line change (T9).
6. No structured security events; failures go to the game log via `ModApi.Log` (`ModApi.cs`). Note only; o11y-review owns log structure.

Single points of failure: `RteTile.Decode` is the sole gate for local and CDN bytes (hardening it covers E1+E2 at once), and `CdnTilePolicy.TileUrl` is the sole gate for outbound tile URLs.

Documented-but-not-implemented check: the previous revision claimed an engine patch/backup/`--verify` pipeline (`Program.cs`, `Makefile:253-255`) that does not exist and has been removed above. Remaining claims were re-read against code: the `MODLET.md` config-validation claim matches `RealEarthConfig.Validate()` (`RealEarthConfig.cs:286-471`); `SECURITY.md`'s CDN claim was false and is corrected in that file; the `BACKUP_RESTORE.md` checksum/refuse-overwrite claims match `backup_artifacts.sh:74-79,112-118,129-145` and its restore-drill claim is implemented (`scripts/artifacts_drill.sh`, `ci.yml:51`).

## 7. Abuse cases

- **Pack poisoning.** A publisher ships a "free full-Earth" pack with altered heights/population; operators install it; players get unfair geometry/loot. Path: E2 accepts any well-formed RTE1 (`RteTile.cs:48`), gap 1.
- **CDN-borne terrain rewrite.** Whoever controls or compromises the configured https CDN rewrites tiles; they pass the magic gate and the full decode, then land in the disk cache, poisoning later sessions even after the CDN is fixed. Path: `TileStreamer.cs:602-613`, gap 1.
- **Pipeline-cache poisoning.** A compromised workstation or hostile mirror serves Terrarium PNGs once; they are stored to `data/cache/terrarium` and every future rebuild trusts them (`elevation.py:263-275`), silently baking altered elevation into new packs. Same class as the previous case, offline half of gap 1.
- **Viewer-borne script execution (regression watch).** A shared viewer pack embeds markup in a settlement name; operator previews via `realearth serve`. Today nothing renders it as HTML (`viewer/src/app.ts:273-275` builds text nodes), so this is the scenario to re-test if an HTML sink ever appears. Recorded as scenario, not demonstrated.
- **Half-patched engine via load order.** Another mod JITs a Y-bound method before `RuntimeYDimTranspiler` installs, leaving the engine with mixed vertical bounds: terrain or lighting computed against a different YDim than storage allocates. Documented in `RuntimeYDimTranspiler.cs:11-15`; the trigger is mod ordering, not an attacker, but the failure mode is silent world corruption.
- **Authenticated-player resource churn.** Position spam creates focus churn; each new area triggers bounded CDN/disk loads. Path: focus register (`WorldSession.cs:283-317`) → `TileStreamer.UpdateFromAbsolute` (`TileStreamer.cs:113-141`); bounds: `StreamRadiusTiles`/`UnloadRadiusTiles` (`RealEarthConfig.cs:24-25`), miss cache + prune (`TileStreamer.cs:553-573`), in-flight dedup, stale-focus TTL (`TileStreamer.cs:60,195-211`). Amplification against the configured CDN host is capped today.
- **Client-side enforcement:** none relied on; reveal/debug helpers are config-gated server-side (`MapReveal.cs:36-45`, `DebugRevealFullMap` default false `RealEarthConfig.cs:62`).

## 8. Response readiness (note only)

- Reporting channel documented ([`../SECURITY.md`](../SECURITY.md)); no documented path from "vulnerability reported" to "fix shipped" beyond it.
- Audit trail after an incident is thin: game log lines only (`ModApi.Log`). o11y-review owns log structure; sec-review should treat gaps 1-6 above as its aiming list. Durability of evidence itself is covered by [`BACKUP_RESTORE.md`](BACKUP_RESTORE.md) (artifact archives), not by any log retention policy.
